# Repository audit and maturity assessment

**Review date:** 2026-10-30  
**Scope:** source, research claims, dependency declarations, build/test automation, user interfaces, and repository hygiene.

## Summary

This is a reproducible research prototype with a Python/Streamlit analysis pipeline and a separate static React/Vite results explorer. The repository provides synthetic-data experiments, limited measured-data case studies, a manuscript, reports, figure-generation code, and optional C++ kernels. The checked-in results are useful for research inspection and reproducibility; they are not evidence of deployed energy savings or validated household behavior classes.

The release work adds a documented architecture, methods and limitations, experiment records, software security guidance, CI checks, Docker packaging, Python and web dependency inventories, and a shared ManimGX explainer. The explainer is rendered once and served as a static MP4 by both apps; neither deployment imports the renderer.

## Research design and claim limits

- The principal 365-day result is generated by the project’s own synthetic profile generator. ARI/NMI are recovery against those generator labels, not real-world classification accuracy.
- PCA and K-Means are used for exploratory pattern discovery. Model clusters are not ground-truth consumer behavior categories.
- The UCI load-diagram source provides anonymized client identifiers and no behavior labels. The report does not infer household identities from those IDs.
- The London study covers eleven available CSV archive members and a filtered subset. It is a limited case study, not a representative sample of the full source population.
- The load-shift analysis is an assumption-driven retrospective counterfactual. It changes the modeled load profile and does not observe participant response, estimate causal effects, or demonstrate bill/emissions savings.
- Missingness, coverage filters, normalization choices, clustering selection, and seed sensitivity are documented in the method and per-experiment reports.

## Engineering controls and remaining work

- Python dependencies are pinned; the web app uses a committed npm lockfile. SBOM JSON files are generated from these declarations.
- CI runs the Python tests plus web tests and production build with read-only repository permissions. The paper workflow no longer commits generated PDFs.
- Docker runs as a non-root numeric UID and excludes raw meter data, environment files, VCS metadata, and caches from the build context.
- The C++ engine is optional; Python/scikit-learn remains the reference and fallback. Performance claims must remain tied to the benchmark environment and workload.
- Continue dependency advisory review, check in refreshed SBOMs when pins change, build the container in a Docker-enabled environment, and compile the manuscript in a TeX-enabled environment before a formal release.
- Confirm GitHub LFS object availability and run a clean clone/install smoke check after publication.

## Reproduction entry points

The repository root README links the architecture, requirements, traceability, methodology, limitations, research protocols, benchmarks, SBOMs, security policy, and release artifacts. Use each report’s command and configuration sidecar rather than treating the generated outputs as independently reproduced results.
